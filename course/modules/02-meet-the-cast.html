Meet the Cast

Six files, six jobs. Knowing who does what lets you tell your AI exactly where a change belongs.

A TV weather studio

Picture the evening weather broadcast. A presenter reads from a script, a producer runs the show, a weather station supplies numbers, and a style guide says when to show the umbrella icon. This repo has exactly that crew.

instructions.md The script: always-on rules Claude must follow (the "system prompt")
src/ All the program code
agent.ts The producer: starts the run, wires Claude to the tool
decide.ts The style guide: umbrella rule and clothing rule
quest-clothing.ts The rehearsal: checks the clothing quest is done
tools/ Things Claude may ask to run
get_weather.ts The weather station: fixture data or a real HTTP lookup
tests/ Automatic checks that run with no API key

How the producer hands Claude its tools

Tools don't reach Claude one by one. agent.ts packs them into a small MCP server, like a toolbox with a label on the lid.

src/agent.ts 
export function weatherMcpServer() {
  return createSdkMcpServer({
    name: 'weather-agent-sdk',
    version: '0.1.0',
    tools: [getWeatherTool],
  });
}
PLAIN ENGLISH

Define a reusable function other files can use, called weatherMcpServer.

It builds a toolbox using a helper from the SDK...

...labels the toolbox with a name...

...and a version number...

...and puts exactly one tool inside: get_weather.

Close the toolbox.

Done.

Why this matters when steering AI

Adding a second tool means two edits: write it in src/tools/, then add it to this tools: [...] list (and to the allowed list you'll meet in Module 3). Forget either and Claude will never use it.

Check your understanding

You want the agent to answer in English by default. Which crew member do you change?

Your manager says "umbrella from 50% rain, not 60%". Where does the code change go first?

Your AI assistant wrote src/tools/get_uv_index.ts, but Claude never calls it. What is the most likely missing step?
