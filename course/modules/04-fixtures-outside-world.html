Fixtures and the Outside World

When the agent uses fake weather, when it goes to the real internet, and how secrets stay out of git.

Plastic fruit in the shop window

Shops put plastic fruit in the window: it looks right, never rots, and is identical every morning. The fixture is this repo's plastic fruit: Amsterdam, 14°C, 72% rain, forever.

src/tools/get_weather.ts 
/** Deterministic Amsterdam fixture — unit tests pass without network or API key. */
export const FIXTURE_WEATHER: WeatherObservation = {
  city: 'Amsterdam',
  date: '2026-09-21',
  temperatureC: 14,
  precipitationProbability: 72,
};
PLAIN ENGLISH

A note: this data is deterministic, so tests never need the internet or a key.

A shared constant shaped like a WeatherObservation:

City: Amsterdam.

Date: 21 September 2026.

14 degrees Celsius.

72% chance of rain (high enough for an umbrella).

Done.

Three doors inside fetchWeather

Every lookup walks through fetchWeather and exits through one of three doors. Which one depends on two environment variables.

1
Fixture door (default)

No WEATHER_BASE_URL set, or WEATHER_USE_FIXTURE=1. Returns the plastic fruit with your city and date pasted on.

2
Safety-net door

Fixture was switched off (WEATHER_USE_FIXTURE=0) but there's still no URL. Rather than crash, it hands back the fixture anyway.

3
Real-world door

A WEATHER_BASE_URL exists and the fixture isn't forced: it makes a real HTTP request.

src/tools/get_weather.ts 
  const response = await fetch(weatherUrl(input.baseUrl, input));
  if (!response.ok) throw new Error(`Weather request failed with ${response.status}`);
  return (await response.json()) as WeatherObservation;
PLAIN ENGLISH

Build the full address and ask the weather server, then wait for the reply.

If the server said anything other than "OK", stop loudly and include the status code (like 404 or 500) in the error.

Otherwise read the reply as JSON and trust that it has the WeatherObservation shape.

🔍
Notice the "trust"

as WeatherObservation is a promise to the compiler, not a check. If a real server returns different field names, nothing complains until something downstream reads undefined. A runtime validation step would catch it.

Keeping the key out of git

The live lane needs ANTHROPIC_API_KEY. The repo treats it like a house key: kept on you, never taped to the front door.

src/agent.ts 
export async function runWeatherAgent(prompt: string) {
  if (!process.env.ANTHROPIC_API_KEY) {
    throw new Error('Set ANTHROPIC_API_KEY in the environment. No secrets in git.');
  }
PLAIN ENGLISH

The live-lane function, which takes your question as text.

First, check: is there an API key in the environment?

If not, stop and ask for a key in the terminal before running the live path.

(Only past this gate does any money get spent.)

ANTHROPIC_API_KEY Set it in the terminal for a live run. Do not save it to a file.
.gitignore A list of files git should not track. The API key stays in your terminal, not in a file.
